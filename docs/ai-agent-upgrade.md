# Shopify WhatsApp AI agent upgrade

## Scope shipped

The agent already supported OpenAI/Anthropic provider keys, hybrid knowledge retrieval, synced Shopify catalog recommendations, WhatsApp carousels, a customer playground, usage logs, reply caps, flow precedence, and human handoff. This update builds on those features.

- Shopify brands get an onboarding card based on the supplied reference: connected store, Get started, support/sales capabilities, and a clear path into setup.
- Get started imports published store policies for admins with a connected Shopify store. Setup also has an explicit import/retrain control. This imports Shopify's policies, **not every storefront page**. Product recommendations use the existing synced catalog.
- Retraining replaces one deterministic account/store policy document. Manually authored FAQs and instructions remain separate. Empty/failed upstream imports preserve existing training. Indexing failures are reported with a recovery path.
- Setup shows active catalog variant count, policy import date, and carousel enablement. Connected means the saved connection status; it is not a successful live health check.
- Order-related turns attempt a read-only Shopify lookup using the saved contact phone, with at most three phone variants and one five-second abort deadline. Results require an independent phone match. No customer-supplied order number, email, or phone expands the lookup scope.
- Cached orders remain a fallback, with source and sync timestamps in the prompt. Both live and cached results require a full phone match or the known Indian domestic form of a WhatsApp +91 number; fuzzy eight-digit suffix matching is insufficient. Live search is a bounded recent-order lookup, not exhaustive order history. Missing/redacted phones cannot establish ownership.
- Product browsing stops when the customer switches to order support or asks for a human. Old browse intent does not survive an intervening support turn.
- Both providers receive the same commerce rules: explain documented policies, clarify ambiguous orders, do not invent delivery dates or claim refunds/cancellations/edits were executed. These are prompt rules; executable store mutations are not introduced.
- Playground adds common test questions and resets the transcript when changing simulated customers.

### Guided selling and delivery

- Explicit budgets and size labels are now parsed from the active shopping transcript and enforced against catalog rows before the result limit. Supported budget forms include under/below, up to/at most, minimum/maximum, between, currency-marked amounts, and a numeric reply to a budget question. Later amounts can revise the budget while retaining an explicitly selected currency. These are deterministic English patterns, not unrestricted natural-language extraction.
- Currency constraints never perform exchange-rate conversion. An ambiguous `$` asks for the currency; bare amounts use catalog currency. Invalid prices, unavailable cached variants, incompatible sizes and unknown currency on a budget result are excluded. Size matching supports common aliases, fractional labels and explicit UK/US/EU labels without converting between size systems.
- Both merchant-curated variant lists and ordinary catalog search use the same constraints. Filtering happens before selecting up to four recommendations; a single valid product and products without images can now be offered as text.
- Automatic replies, the playground and inbox drafts share the same filtering and server-generated product detail/checkout-link formatting. The model writes an introduction; the application supplies catalog facts and exact variant links.
- Carousels are used only when enabled and every selected item has an image. Text fallback includes the matching catalog details. Checkout links respect the merchant's Enable product sends switch; with it off, the reply contains informational product text only.
- An explicit Meta client rejection can fall back to text. A confirmed Meta receipt followed by a local database failure, or an uncertain network/server send outcome, suppresses automatic fallback to avoid duplicate messages.
- Search remains bounded: up to 50 candidates per keyword query, eight keyword fallbacks, twelve knowledge hints and twenty curated IDs. Constraints persist within the available conversation context, not beyond its configured history window. Inventory and prices are synced data; live stock/price validation and persistent shopping memory remain future work.

## Merchant setup

1. Open AI Agents and choose Get started.
2. If policy access is denied, grant `read_legal_policies` in the Shopify app and reconnect. New OAuth connections request this scope by default, unless deployment configuration overrides `SHOPIFY_SCOPES`.
3. A super admin opens **Brands → expand the brand → WhatsApp AI model** to select the provider/model and add/test the provider key. They can optionally configure the embeddings key for semantic knowledge retrieval. Keyword retrieval works without it. Brand admins manage the system prompt, reply switches, reply cap, handoff and knowledge in AI Agents.
4. Import policies, add FAQs/size guides in Knowledge, and check the catalog sync and Sell on WhatsApp settings.
5. Test a real contact's order lookup, an unknown order, multiple orders, a policy question, a return execution request, and human handoff.
6. Enable automatic replies after testing. Importing policies never changes the agent's active/auto-reply switches.

Apply `20261014060149_super_admin_ai_model_controls.sql` when deploying the centralized model controls. It restricts authenticated database writes to behavior fields, while scoped super-admin routes manage model credentials through the service role. Existing model configurations remain in place. Existing AI knowledge migrations and Shopify product tables must also be installed.

## Integration limits

- The existing Shopify integration pins `2025-01` and uses REST. This change reuses that integration. Shopify now treats REST as legacy; migrate the integration to a supported GraphQL API version as a separate compatibility project, with contract tests for order, fulfillment, policy and catalog payloads. See [REST reference](https://shopify.dev/docs/api/admin-rest/latest), [Order](https://shopify.dev/docs/api/admin-rest/latest/resources/order), and [Policy](https://shopify.dev/docs/api/admin-rest/latest/resources/policy).
- Shopify order access normally covers the last 60 days; older history requires approved access. Missing customer fields can reflect protected-data permissions. See [protected customer data](https://shopify.dev/docs/apps/launch/protected-customer-data).
- New policy imports require explicit admin interaction; this is not a scheduled crawler or continuous knowledge sync.
- Live provider accuracy, Shopify permissions and WhatsApp delivery need a connected-store smoke test. Unit tests use synthetic data and do not send customer messages.
